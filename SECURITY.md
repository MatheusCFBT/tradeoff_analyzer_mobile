# Security Policy

## Supported Versions

Security fixes are applied to the latest stable release of the application
and the `main` branch.

Earlier versions may not receive security fixes. We recommend updating
to the latest available stable release.

## Reporting a Vulnerability

Please do not open a public issue to report a vulnerability.

Submit your report through email:
- GitHub Private Vulnerability Reporting, through the repository's Security tab;
- Email: matheusterzini@gmail.com.

When possible, include:

- A description of the vulnerability and its potential impact.
- The affected application version or commit.
- The platform and operating system version.
- Steps to reproduce the issue.
- A minimal example, relevant logs, or screenshots.

Remove personal data, passwords, tokens, and other credentials from attachments.
If the issue involves an exposed credential, identify its location without
including its value.

## Handling Reports

The maintainer will review the report and may request additional information.

Once the issue is confirmed, the maintainer will assess a fix and an appropriate
way to notify affected users.

There is no guaranteed response or resolution timeframe.

Please coordinate public disclosure with the maintainer to allow time
for investigation and a fix to become available.

## Scope

This policy covers the code, configuration, and artifacts distributed
by this project.

Issues in third-party services or dependencies should be reported to their
respective maintainers. If they affect this application, please also notify
the project maintainer.
